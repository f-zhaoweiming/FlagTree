# SDK04 · 为普通双输出 FP16 Add+LayerNorm 增加厂商 FP32 融合路径

关联本地 [Issue SDK04](ISSUE.md)。对于匹配的二维 FP16 输入、逐列 FP16 权重和 FP16 输出，包装层将实际 FP16 操作数无损提升为 FP32，调用 `xpu_flash_ops.add_layernorm` 的 FP32 融合实现。残差加法和归一化在该调用中完成，成功后将请求的每个输出各写回 FP16 一次。该路径处理可选偏置和残差，量化输出使用既有分派。[代码补丁](fix.patch)

**验证**　16×64、64×1024、577×1024、2048×2048 各测随机与高偏置输入。八项均返回成功，主输出和残差输出分别满足相对于原始 FP32 eager 的 RMSE、最大绝对误差、最大归一化误差均不劣于 FP16 eager。可选输出、非连续输入、输出与输入复用以及不同 epsilon 的四组回归也通过。端到端耗时包含转换、临时张量、核调用、写回和同步。[逐项精度与耗时](../FP16/p800-results.json) · [边界回归](../FP16/contract.json)

此补丁以官方 wheel 解压目录为根。可单独应用，在该环境运行 `python verify_wrappers.py --operator add_layernorm`。个人 Docker 准备程序校验上游 wheel 并记录修复后模块指纹。[准备程序](../XFA/prepare_ops.py)

两轮独立进程的端到端加速比范围为 **0.347–0.472×**，计算口径为同卡 FP16 eager 同步耗时除以修复后公开入口同步耗时。[两轮逐项原始指标](../FP16/p800-results.json)

## 首版直接读写 FP16 的双输出单核

KL3 Cluster 核读入连续 FP16 的两张输入矩阵和两条仿射参数，在片上以 FP32 完成加法、均值、中心化方差和仿射计算。两种版本均将残差和归一化结果直接写入调用者的 FP16 缓冲。`round_residual=False` 用 FP32 和计算归一化，`True` 用该和舍入到 FP16 后的值计算归一化。首版 1024 和 2048 列分别由 2 和 4 个 core 协作处理一行。该入口支持默认流、二维连续无梯度 FP16 张量、64 字节对齐、非重叠的输出缓冲。[设备源码](dual_layernorm.xpu) · [可调用的 Python 入口](dual_layernorm.py) · [启动代码](launch.c)

```python
from dual_layernorm import DualLayerNorm

# build_dir 指向一个尚不存在的目录。每个列宽和舍入策略只需构建一次。
kernel = DualLayerNorm(build_dir, columns=x.shape[1], round_residual=False)
norm, residual = kernel(x, y, weight, bias, output_buffer, residual_buffer)
```

个人 Docker 中完成两个独立计时进程，每轮每种路径 40 次，按轮次交替顺序，统计单次调用至设备同步完成的中位数。预热和编译在计时窗口外。eager 返回新张量，两步实现将加法直接写入残差缓冲，并将 LayerNorm 结果复制到主输出缓冲。精度参考使用同一份原始 FP32 输入和参数，分别比较两个输出相对参考的 RMSE、最大绝对误差和最大归一化误差，三项均须不劣于 FP16 eager。

| 形状 | 输入 | 不舍入相对 eager | 不舍入相对两步 | 先舍入相对 eager | 先舍入精度 |
|---|---|---:|---:|---:|---|
| 16×64 | 随机 | 1.390–1.397× | 1.572–1.604× | 1.370–1.394× | 通过 |
| 16×64 | 高偏置 | 1.374–1.375× | 1.552–1.567× | 1.383–1.400× | RMSE 超限 |
| 64×1024 | 随机 | 1.411–1.430× | 1.500–1.511× | 1.439–1.446× | RMSE 超限 |
| 64×1024 | 高偏置 | 1.407–1.412× | 1.476–1.527× | 1.450–1.511× | 通过 |
| 577×1024 | 随机 | 1.055–1.078× | 1.235–1.273× | 1.055–1.100× | 通过 |
| 577×1024 | 高偏置 | 1.042–1.095× | 1.211–1.266× | 1.044–1.103× | 通过 |
| 2048×2048 | 随机 | 0.756× | 0.859–0.862× | 0.729–0.736× | RMSE 超限 |
| 2048×2048 | 高偏置 | 0.743–0.758× | 0.852–0.853× | 0.722–0.737× | 最大归一化误差超限 |

不舍入版本 8/8 组双输出通过，先舍入版本 4/8 组通过。两个版本的残差都与 FP16 eager 逐元素相等。独立发射跟踪验证每个单核候选只有一次 Cluster 发射，eager 为两次，两步实现为三次，其中一次为 memcpy。六个自研二进制全部解码，厂商二进制含未解码指令。该单核作为独立入口提供，正式包装层仍使用前述路径。[全部误差、两轮耗时与机器码指纹](dual-output-results.json) · [同输入测量脚本](bench_dual_layernorm.py)

## 2048 列不舍入残差的调用和归约优化

2026-11-26 在同一台 P800 的物理 1 号卡、同一个人 Docker 实测。原始 FP32 输入与参数的哈希与首版八组逐一相同。首版在 2048×2048 随机输入上耗时 66.91 µs，同轮 FP16 eager 为 50.61 µs。下表给出新版两轮独立进程的结果，每项取 40 次同步调用的中位数。[逐项双输出误差、原始计时及发射记录](schedule-results.json)

| 形状 | 输入 | 单核 µs，两轮 | eager µs，两轮 | 相对 eager | 相对两步 |
|---|---|---:|---:|---:|---:|
| 16×64 | 随机 | 29.85 / 30.77 | 84.97 / 86.77 | 2.820–2.847× | 3.147–3.182× |
| 16×64 | 高偏置 | 28.86 / 30.32 | 82.96 / 85.17 | 2.809–2.875× | 3.150–3.252× |
| 64×1024 | 随机 | 26.21 / 21.67 | 76.63 / 64.69 | 2.924–2.985× | 3.234–3.246× |
| 64×1024 | 高偏置 | 21.39 / 21.96 | 63.62 / 63.60 | 2.896–2.974× | 3.177–3.246× |
| 577×1024 | 随机 | 19.41 / 19.99 | 32.72 / 33.87 | 1.686–1.694× | 1.927–1.932× |
| 577×1024 | 高偏置 | 19.86 / 19.68 | 33.47 / 33.80 | 1.685–1.718× | 1.896–1.969× |
| 2048×2048 | 随机 | 47.17 / 47.27 | 48.28 / 48.32 | 1.022–1.023× | 1.177–1.187× |
| 2048×2048 | 高偏置 | 46.79 / 47.38 | 47.60 / 47.41 | 1.001–1.017× | 1.172–1.187× |

不舍入残差的归一化和残差输出全部通过，相对于原始 FP32 参考的每项误差均不劣于 FP16 eager。残差输出和 FP16 eager 逐元素相等。先舍入残差的候选仍为 4/8。2048×2048 高偏置第二轮仅领先约 0.03 µs，应按基本持平看待。对错形状、错 dtype、别名、非连续、未对齐和非默认流的拒绝用例通过，1、33、385 行尾块和运行中变更 bias 的用例也通过。

**调用开销。** 保持旧设备二进制相同，只将逐张量的 Python 校验合为一次 C++ 调用，同时逐次检查实际张量、别名、设备和流。2048×2048 交叉对照的 50 次提交中位数从 42.43 降到 11.77 µs。保持新入口相同、只换设备二进制，调用至同步完成从 59.77 降到 53.17 µs。诊断进程与八组端到端进程分别计时，窗口间的绝对值有差异。[带校验的入口](checked_launch.cpp) · [交叉试验与设备消融代码](profile_dual_layernorm.py)

**搬运、归约与跨核同步。** 在热缓冲上由 C 连续提交 32 次，每种设备程序测 18 轮。空发射 2.63 µs，同样搬入两张矩阵并写回两张矩阵的对照 20.54 µs。单做两次跨核屏障增至 24.45 µs。逐点对照 32.63 µs，加入核内局部归约为 33.22 µs，恢复整行统计量交换的旧核为 43.60 µs。两次屏障的 3.91 µs 已包含在交换与等待的 10.38 µs 差额里。矩阵逻辑读写量为 32 MiB，另有权重和偏置。该测量包含缓存效应。保持其他旧代码相同，只异步写残差，设备时间从 43.60 变为 43.47 µs。

**设备修复。** 每核在 FP32 中以切片首元素为中心计算局部均值和方差，归并时加上切片均值与整行均值之差的平方。交替使用两套片上统计缓冲，每轮只交换一次统计量。新版每行四核、每核 512 列为 39.91 µs；改为每行两核、每核 1024 列后为 36.60 µs。反汇编中静态 `sync_group` 从 6 处减为 5 处，`mfence` 从 15 处减为 14 处，归约少一次片上读写遍历。调用跟踪确认 2048×2048 的实发单核、12 个 Cluster 和每个 Cluster 的 64 个 core。复译的新旧机器码 SHA-256 与发射记录一致。[首版 LLVM IR](../../../../review-local/p800-interface-benchmark-20261126/sdk04-schedule/old.ll) · [新版 LLVM IR](../../../../review-local/p800-interface-benchmark-20261126/sdk04-schedule/wide.ll) · [新版反汇编](../../../../review-local/p800-interface-benchmark-20261126/sdk04-schedule/wide.asm)

**与厂商 eager 的剩余差距。** 实际 ATen 中间结果是连续 FP16 残差，发射依次为厂商 Add 和 LayerNorm。预先排队 16 和 32 个命令后，eager 的两个核合计分别为 37.14 和 37.26 µs，旧单核为 47.27 和 47.34 µs，新单核为 40.34 和 40.37 µs。大尺寸端到端的微弱优势来自调用缩短，设备侧仍落后 3.11–3.19 µs。厂商 wheel 提供设备镜像，两个镜像分别有 6 和 124 个指令字未解码，现有证据尚不能把剩余差距分配到某条厂商指令。两步对照实发三次，其中一次是输出复制。本轮修复作用于独立 KL3 入口，官方包装层继续使用其已记录的分派。[厂商实发指纹和反汇编](dual-output-results.json)

## 为什么 2048×2048 的端到端收益较小

在同一台 P800 的物理 1 号卡上，固定 2048 列和正式单核的机器码，在两个独立进程中扫描 8 种行数。每个形状、每条路径各测 32 次，随机交替顺序，在同一条流预排 24 个命令后测量单次设备事件。下表给出两轮各自的中位数，单位为 µs。两轮占用监测均通过。[原始数据和二进制指纹](size-diagnosis.json)

| 行数，列数固定为 2048 | 融合核，两轮 | eager 两核合计，两轮 |
|---:|---:|---:|
| 384 | 11.96 / 11.65 | 16.89 / 16.66 |
| 1920 | 34.97 / 35.31 | 35.83 / 36.00 |
| 1921 | 37.94 / 37.74 | 36.30 / 35.89 |
| 2048 | 40.69 / 40.34 | 37.91 / 37.26 |
| 2304 | 40.89 / 40.35 | 39.19 / 39.14 |

每行两个 core，每个 Cluster 每轮处理 32 行，12 个 Cluster 合计 384 行。1920 行刚好 5 轮。1921 行触发第 6 轮，单核增加 2.43–2.96 µs；2048 行的第 6 轮只有 4 个 Cluster 有工作。增加到 2304 行填满该轮，单核仅再增加 0.01–0.20 µs。2305 行触发第 7 轮，又增加 2.91–3.55 µs。两种形状均已发射到全部 12 个 Cluster。[设备分块](dual_layernorm.xpu)

在 2048 行的诊断对照中，每个 core 单独归一化自己的 1024 列切片需 34.17–34.84 µs，仅在相同的半行算法中加回共享内存栅栏和 Cluster 同步后为 40.78–41.14 µs。该对照少了两个切片之间的真实统计量交换，归一化输出与正式核不同。实发正式核中，写入片上均值与方差之后依次出现 `mfence`、`sync_group` 和共享内存读取；异步残差写回也在该同步点前发起。等待、DMA 完成与按轮分块的影响重叠，不能把约 6 µs 解释为融合相对 eager 的净损失。[正式机器码](../../../../review-local/p800-interface-benchmark-20261126/sdk04-schedule/wide.asm)

保留完整归约且保持双输出逐位相同，单独四倍展开“输入相加并累加统计量”的循环节省 1.07 µs，单独展开归一化输出循环节省 0.45 µs。两段同时展开节省 1.36–1.51 µs，仍比同轮 eager 的设备时间多 1.27–1.71 µs。仅将残差 DMA 延至行同步后节省约 0.32 µs。等价候选已通过本轮随机与高偏置输入相对正式核的逐位比较。运行位置在诊断脚本内，正式路由和端到端数字沿用上节八组复测。[诊断脚本](../../../../review-local/p800-interface-benchmark-20261126/row_diagnosis.py)
