# SDK02 · 为单卡一维复数 FP16 增加 FP32 计算兼容路径

关联本地 Issue [SDK02](ISSUE.md)。调用方先尝试创建原生复数 FP16 计划。仅当计划返回 14 时，销毁原句柄并重新创建复数 FP32 计划，将实部和虚部转为 FP32，调用厂商 `cufftExecC2C`，最后一次写回 FP16。其他错误直接传播。计划与创建它的设备和流绑定，释放前等待该流完成。[执行代码](xfft_fp16.py) · [完整代码差异](fix.patch)

**P800 验证**　测试使用相同的 FP16 输入，对照 CPU FP64 的未归一化正、逆变换。每个长度各有随机与复数脉冲输入。逐分量检查有限性和误差，容差为一个 FP16 ULP 加上按输入绝对值和计算的 FP32 舍入余量。另行统计与 FP64 结果直接舍入到 FP16 的逐分量差异。本次共检查 13,312 个实数分量，12 项都通过该接口回归检查。

| 长度 | 通过项 | 与 FP64 最终舍入不同的分量 | 最大绝对误差 | 同步单次耗时中位数范围 |
|---:|---:|---:|---:|---:|
| 128 | 4/4 | 0 | 0.011178 | 130.8–137.4 µs |
| 512 | 4/4 | 0 | 0.015572 | 348.4–366.2 µs |
| 1024 | 4/4 | 8 | 0.030401 | 546.7–576.6 µs |

耗时包含输入转换、计算、输出转换和同步，复用已创建的计划。所有设备结果使用默认流、连续布局、batch=1。原生 FP16 接口在该发布包中仍返回 14，性能汇总把兼容路径独立记录。[测试脚本](verify_xfft.py) · [P800 全部结果](p800-results.json)
